KORG TRINITY - INSERT / MASTER EFFECT BLOCKS  (block layout decoded; per-effect 16 param bytes NOT transcribed)
=================================================================

What Korg documents in the MIDI implementation (Trinity V1 guide + TR-Rack text):
  Program:     bytes 305-392 "INSERT FX1..4 (22 bytes x 4)" PARA 13,00..17,??   ($ ignored in Drum mode, # in Combi)
               bytes 393-432 "MASTER EFFECT (40 bytes)"     PARA 18,00..1A,??
  Combination: bytes 20-195  "GROUP 1~8 INSERT FX (22 x 8)" PARA 09,00..30,??
               bytes 196-235 "MASTER EFFECT (40 bytes)"     PARA 31,00..33,??
The block layout (type/size/pan/sends) is given only in the SONG table (TABLE 8) -- see below.
What is NOT in the MIDI implementation are the 16 per-effect parameter bytes. Those tables
(OFS 0..15 per effect, with DATA hex range and value range) are in Korg's separate, machine-readable PDF
  "TRINITY Effects MIDI System Exclusive" (Trinity_FX.pdf, 864 KB)
  https://www.korg.com/us/support/download/manual/1/213/3298/
  https://cdn.korg.com/us/support/download/files/f911fe327cfcdd5a1a23e1b5fe92d4c5.pdf
  (not downloadable from this sandbox's shell; WebFetch confirms e.g. "Amp Simulation: OFS0 Amplifier Type
   00..02 (SS, EL84..), OFS1 Wet/Dry 00..64, OFS2 Wet/Dry Src 00..19, OFS3 Wet/Dry Amt 9C..64 (-100..100)";
   "Compressor: OFS0 Sensitivity 01..64, OFS1 Attack 01..64 ..."; "Limiter: OFS0 Ratio 00..83 (1.0:1..inf:1)".)
  -> Next step if effects are needed: fetch that PDF (e.g. by the user) and transcribe the OFS tables.

BLOCK LAYOUT -- documented by Korg in the Trinity guide's "[TABLE 8] SONG SEQUENCE DATA" (scan page 190,
research/scans/p190_table8_song.png), whose bytes 20-235 are the same 8 insert groups + master block as a
combination. Cross-checked with the TR-Rack Ctrlr panel's SysEx decoder (github.com/FRDTom/TR-Rack-Editor,
Lua setProg; its 1-based SysEx positions converted to 8-bit record offsets), Toluene's ParameterIDs.h,
and statistics over ~500 programs / 256 combis in the user's PCG files.

22-byte INSERT FX block  (Korg TABLE 8 "GROUP 1 INSERT EFFECT" 20..41)
  +0..+15  EFFECT PARAMETERS (16 bytes, OFS 0..15; meaning per size+type, see Trinity_FX.pdf)
  +16      b0-6 FX TYPE (doc: 00..1C = 0..28 when size 1; 00..33 = 0..51 when size 2; 00..12 = 0..18 size 4)
           b7   CASCADE 0:OFF 1:ON
           NOTE: real data has bit 6 set on most active effects (0x40|type, e.g. 0x47, 0x6F); the Ctrlr panel
           treats bit 6 as the effect ON/OFF toggle and Toluene has separate "enable" params (13,04-06).
           -> decode TYPE = b & 0x3F, ON = (b>>6)&1, CASCADE = b>>7.
  +17      SIZE 0,1,2,3 : 0 (none), 1, 2, 4   (sum over the blocks of one chain <= 4)
  +18      PAN   00..7F : L00..R127
  +19      WIDTH 00..7F : 0..127
  +20      SEND 1 00..7F
  +21      SEND 2 00..7F
  Program: 4 blocks at 305/327/349/371; only blocks 1-3 are ever used (block 4 size always 0 in all data;
    TR-Rack/Toluene expose 3 insert FX with IDs size 13,00-02 / enable 13,04-06 / type 13,08-0A).
    The Ctrlr panel reads pan/width/send1/send2 only from block 3 (the chain output); blocks 1,2,4 hold
    40 7F 00 00 in practically all data.
  Combination/Song: 8 blocks at 20 + 22*k. Data behave like two chains of 4 blocks (1-4, 5-8),
    e.g. sizes (2,2,0,0,2,2,0,0).

Timbre/track byte 254 "INSERT EFFECT SIZE": doc (combi, V1): 0 OFF, 1 Size 1, 2 Size 2, 3 Size 4,
  4..B = Timbre 1..8 (song: 4..13 = Track 1..16). Observed combis: T1=3, T2=5, T3=5, T4=3 (Strings+Vibs),
  T1=3, T2=8, T3=5, T4=3 ... A timbre pointing at itself (T2=5 under the doc's "4 = Timbre 1") makes no
  sense; the data fit better "5 = share Timbre 1's chain, 8 = share Timbre 4's chain" (value-4 = timbre no.
  counted from 1, with 4 unused?).
  UNRESOLVED: verify on hardware / later OS docs before relying on it.

40-byte MASTER FX block  (Korg TABLE 8 "MASTER EFFECT" 196..235)
  +0..+15  EFFECT 1 PARAMETERS (16 bytes)
  +16      FX TYPE effect 1: 00..05 (doc). Data also use b6 (ON, per Ctrlr "pMasterToggle-1") and
           b7 (routing / connect-in-series, Ctrlr "pMasterRoute", Toluene 18,00) -> TYPE = b & 0x3F.
  +17      PAN   FF, 00..7F : OFF, L00..R127      (0xFF = OFF is the most common value)
  +18      RETURN LEVEL 00..7F
  +19..+37 EFFECT 2: same 19-byte layout (16 params, TYPE 00..07 with b6 = ON, PAN, RETURN LEVEL)
  +38      LOW EQ   DC..24 : -18..+18  (signed)
  +39      HIGH EQ  DC..24 : -18..+18  (signed)
  Toluene: MFX1 output level/mod source/mod amount = 19,0B-0D and MFX2 = 1A,14-16, i.e. inside the
  16 parameter bytes of each master effect.
